# Mining Autonomy — START HERE

## Mission
Build an exhaustive, evidence-backed map of legal/ToS-compliant autonomous earning mechanisms, then turn the strongest candidates into a conservative implementation/experiment stack.

Primary priority: **server-native online automation** — software/bots/agents/nodes that can run continuously on a rented or owned server and earn from simple, automatable work with minimal human input.

Secondary priority: **all other passive or semi-passive income models**, including monetizing home-computer resources, hardware, capital, digital assets, and systems that require an initial build or investment.

## Current phase
Discovery Runs **001–062 are COMPLETE**. The project is now in **Implementation / Experiment Phase**. Do not reopen broad discovery unless implementation exposes a genuinely missing economic mechanism.

Implementation target: a legal server-native agent that can observe permitted paid work/services, normalize opportunities, estimate execution cost and expected margin, reject unsafe/non-compliant/negative-EV work, and eventually execute positive-margin work only after explicit authorization for credentials, money-moving actions, paid infrastructure or identity/KYC steps.

- Work in medium-sized coherent stages; avoid one huge fragile run.
- If a stage is too small, make the next materially broader/deeper.
- Save progress after every stage so any new chat can resume exactly.
- User interaction can stay minimal: while unfinished, report only `в процессе`; at true completion report `завершено` unless the user asks a question.
- The user may interrupt or change scope at any time.
- Demand/fill rate must be measured rather than inferred from provider/listing counts.

## Implementation ordering
1. Rank candidates by expected net return, capital/recurring cost, autonomy, demand evidence, compliance/KYC/geography and complexity.
2. Revalidate top candidates with current primary sources.
3. Design low/capped-cost experiments.
4. Implement read-only adapters, offline/dry-run evaluators, quality/policy gates and audit trails.
5. Measure real public demand/economics where permitted.
6. Only after explicit authorization, add any credentialed, paid, KYC, wallet, task-acceptance, publication or settlement component.
7. Combine successful branches into an autonomous control plane.

## Research taxonomy retained for reference
### Tier A — server-native autonomous earning
Compute providers, storage providers, network/relay nodes, AI-incentive networks, validators/indexers/orchestrators, legitimate API/job markets, resource marketplaces, autonomous services.

### Tier B — autonomous but not ordinary VPS/server-native
Residential bandwidth sharing, home GPU/CPU sharing, spare disk, physical DePIN, device-based contribution.

### Tier C — capital-based passive/semi-passive
Deposits, bonds, staking, lending, liquidity provision, dividend/REIT-like instruments, revenue-sharing assets. Risk must be explicit.

### Tier D — build-once digital income systems
Micro-SaaS, paid APIs, affiliate/content assets, licensing, stock media, templates, print-on-demand, digital products, data products, automated storefronts.

### Tier E — adjacent / speculative / rejected
Non-paying, ToS-incompatible, fake-activity, scam, dead or economically unsuitable ideas remain documented to prevent rediscovery.

## Hard safety / integrity boundaries
Do not design or use:
- CAPTCHA bypass;
- fake clicks/views/engagement;
- ad fraud;
- spam;
- credential abuse;
- unauthorized scraping/access;
- multi-accounting where forbidden;
- evasion of KYC/geofencing/platform limits;
- botting human-only tasks contrary to ToS;
- theft of compute/bandwidth/electricity;
- malware, cryptojacking, or deceptive installs.

Without explicit user authorization, do not spend money, fund/create wallets for value movement, stake/deposit, rent paid infrastructure, create paid accounts, submit KYC/bank onboarding, accept paid work carrying liability, publish monetized services under the user's identity, or settle transactions. Read-only observation, public-data analysis, local/CI dry runs, architecture and capped simulations may continue.

Implementation is COMPLETE only when either:
1. a documented autonomous stack demonstrates confirmed positive economics on real, permitted tests; or
2. reasonable implementation candidates are exhausted and control passes confirm no viable implementation.
